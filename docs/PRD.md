# 企业 ChatBI 查数平台：PRD

**目标：让业务人员用自然语言查数、出图，同时保证越权不可能、SQL 只读、口径可控、质量可评测。** 第一版面向内部几十到几百人，一个会话绑定一个数据源，不做跨数据源联查和会话分享。

## 1.1 角色与权限矩阵

一个人只属于一个团队。权限逐级收窄：管理员授权给团队的范围 ⊇ 团队负责人授权给员工的范围。

| 能力                         | 管理员   | 团队负责人                | 员工           |
| -------------------------- | ----- | -------------------- | ------------ |
| 用户、团队、角色管理                 | 全平台   | 无                    | 无            |
| 数据源管理（含 Excel/CSV 上传）      | 全部    | 无（可上传本团队的 Excel/CSV） | 无            |
| 配置表、字段对团队的可见范围             | 可以    | 无                    | 无            |
| 在团队范围内配置员工可见的表、字段          | 可以    | 仅本团队，且不超出管理员授权       | 无            |
| 语义（别名）与指标                  | 创建平台级 | 创建团队级                | 创建个人级（仅自己可见） |
| 个人语义、指标提升为团队级              | 无     | 审核通过或驳回              | 发起申请         |
| 模型配置（LLM、Embedding、Rerank） | 配置    | 选择本团队使用哪个            | 无            |
| 查询日志                       | 全平台   | 本团队                  | 仅自己的会话历史     |
| 反馈                         | 查看全平台 | 查看本团队                | 提交           |
| 评测集与回归评测                   | 运行、维护 | 查看结果                 | 无            |
| 提问、查看 SQL、出图、导出            | 可以    | 可以                   | 可以           |

## 1.2 已确认的决策

- 一人一团队；会话创建时绑定数据源，中途不可切换。
- 语义、指标三级：平台、团队、个人；冲突时 个人 > 团队 > 平台，结果解释里标明生效的是哪一级。
- 员工的个人语义与指标对负责人不可见；员工可申请提升为团队级，由负责人审核。
- 模型配置仅管理员可改；团队只能在已配置的模型中指定默认使用哪个；Rerank 为可选。
- 日志与反馈只保存 SQL 和结果摘要（行数、前若干行），并设保留期限；被拦截的请求也要记录，带拦截原因。
- Excel/CSV 数据源默认仅上传者所在团队可见，需管理员授权才能开放给其他团队。

## 1.4 核心流程

1. **提问：** 用户选数据源开会话，提问；系统在其可见范围内检索表和字段，生成 SQL，校验后用只读账号执行，返回表格、图表和解释。
2. **数据源上传：** 上传文件，选择 sheet、表头行、编码、字段类型，预览前 100 行，确认后后台导入，导入后与其他数据源走同一套权限和语义流程。
3. **反馈闭环：** 用户点踩，系统保存快照，负责人处理后可一键转成评测样例，评测集随使用增长。
4. **指标提升：** 员工创建个人指标，申请提升，负责人审核通过后变为团队级，对全队可见。

## 1.5 明确不做

- 跨数据源联查
- 会话分享
- SSO（仅预留认证接口）
- 团队自带模型
- 合并单元格与多级表头的自动解析（提示用户先整理）
