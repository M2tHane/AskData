# 功能完整性检查清单

逐节对照。每条都回答"满足 / 不满足 / 不适用"，不满足的写进缺口清单并标 P0/P1/P2/决策。

## 1. 生命周期与操作入口

- [ ] 对象的每个状态都列出来了，每个状态下用户能做的操作都有入口。
- [ ] 创建：有明显的入口（不只藏在某个 tab 里）；创建前展示关键信息（数量、耗时/成本估算、影响范围）。
- [ ] 进行中：能看到进度；能停止/取消。
- [ ] 停止/失败后：能继续或重试，已完成的部分保留，不需要从头再来。
- [ ] 完成后：能基于它再来一次（重新运行、复制、只重做失败部分）。
- [ ] 删除：存在；进行中的对象不能直接删（先停止）；删除连带的子数据一并处理。
- [ ] 编辑：能改的字段都能改；不该改的（历史快照）明确不可改。
- [ ] 同一操作在列表、详情等各入口都可用，行为、文案一致。
- [ ] 操作完成后界面停在合理的位置（删除后回列表、开始后进详情看进度）。

## 2. 状态与数据真实性

- [ ] 空状态：说明为什么是空的，以及下一步该做什么（带入口或指引）。
- [ ] 加载中：有占位，不会闪出"没有数据"。
- [ ] 进行中：数字实时刷新（轮询或推送），结束后停止轮询。
- [ ] 部分完成：明确标出"已完成 x / 共 y"；比率只按已完成的部分算，并说明口径。
- [ ] 失败/中断：说明发生了什么、可能的原因、已保留什么、下一步怎么办。
- [ ] 指标在不完整数据下不给出错误结论（例：只跑部分题时安全门槛显示"未判定"而不是"未通过"）。
- [ ] 时间、时长用人能读的格式（"12 分钟"，不是"740.6 s"）；时长的口径说清楚（是否含暂停）。
- [ ] 历史记录用当时的快照，后续修改不会改写历史。

## 3. 可逆性、确认与反馈

- [ ] 不可逆操作（删除、覆盖、发布）有确认框，写明后果。
- [ ] 可逆操作（停止、隐藏、筛选）**不弹**确认。
- [ ] 每个操作都有反馈：成功（界面状态变化或提示）、失败（说人话的原因，不是错误码）。
- [ ] 操作进行中按钮禁用，防止重复提交。
- [ ] 耗时长或成本高的操作开始前给出预估。

## 4. 异常、并发与中断

- [ ] 服务重启、worker 崩溃后，对象不会永远卡在"进行中"；用户有办法恢复（停止 → 继续，或自动恢复）。
- [ ] 两个操作交错（停止后马上继续、两人同时操作）不会产生重复数据或错误状态。
- [ ] 外部依赖失败（模型、数据库、对象存储）时给出可理解的提示，已完成的工作不丢。
- [ ] 后台任务被重复投递时不会重复执行或报错。
- [ ] 后端校验所有前端限制（前端隐藏按钮不等于后端禁止）。

## 5. 权限与角色

- [ ] 对 admin / leader / member 逐个检查：能看到什么、能做什么。
- [ ] 没权限的入口直接不渲染，不置灰。
- [ ] 后端每个写接口都有角色检查；越权调用返回明确错误。
- [ ] 敏感数据（SQL、他人数据、密钥）只给有权看的角色。
- [ ] 写操作记审计日志。

## 6. 列表与表格

- [ ] 列有意义且足够：用户做判断需要的信息都在（状态、进度、结果、时间、负责人/备注）。
- [ ] 对齐：数字列右对齐；表头与内容对齐；操作列按钮文字与表头对齐；整行垂直居中；徽标、按钮、文字基线一致。
- [ ] 长文本截断并能看全（title 或展开）；短字段不换行。
- [ ] 数据多时可筛选、搜索、分页或滚动；窄屏有横向滚动而不是挤坏。
- [ ] 行点击和行内按钮不冲突（按钮阻止冒泡）。
- [ ] 进度条、徽标颜色表达状态（完成绿、停止/警告黄、失败红），同时有文字和图标。

## 7. 表单与对话框

- [ ] 合理默认值（默认模型、上次的选择、从原对象预填）。
- [ ] 字段有说明或示例；必填与长度限制前后端一致。
- [ ] 提交失败时保留已填内容，错误显示在对话框内。
- [ ] Esc / 取消能关闭；危险操作按钮用 danger 样式。

## 8. 可追溯与对比

- [ ] 用户能区分多条记录（编号、时间、备注/名称）。
- [ ] 能知道一条记录当时用的配置（模型、版本、参数）。
- [ ] 支持前后对比的场景，对比结果直达明细。

## 9. 文案与视觉

- [ ] 遵守 `chatbi-design-system`：token 颜色/间距、组件、简体中文、按钮动词开头、无感叹号和 emoji。
- [ ] 状态同时有图标和文字。
- [ ] 文案说人话：用户能看懂原因和下一步，不出现内部代码名、错误码、英文状态值。
- [ ] 同一概念全站同一叫法。

## 10. 质量与交付

- [ ] 后端：新状态转换、中断/并发、权限都有测试；`ruff`、`mypy`、`pytest` 通过。
- [ ] 前端：`tsc`、`eslint`、`vitest` 通过。
- [ ] 数据库变更有 migration，测试夹具同步。
- [ ] openapi 与前端类型已重新生成。
- [ ] 容器已重建并在浏览器中验证过真实行为。
- [ ] 验证产生的测试数据已清理。
